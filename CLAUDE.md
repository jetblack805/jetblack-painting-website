# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing/SEO website for **Jetblack Painting**, a Melbourne residential & commercial painting business, live at **https://jetblackpainting.com** (served by Cloudflare Workers). The site is a React SPA plus a pre-rendered static-HTML layer for SEO. Most content changes revolve around suburb landing pages, service pages, and structured data.

## Commands

Package manager is **pnpm** (pinned via `packageManager` in package.json).

```bash
pnpm install
pnpm dev                     # Vite dev server (port 3000, --host)
pnpm build                   # generate static pages → vite build → esbuild server bundle, all into dist/
pnpm check                   # TypeScript typecheck (tsc --noEmit) — no lint config; this is the CI-style gate
pnpm test                    # vitest run
pnpm vitest run <file>       # run a single test file, e.g. client/src/lib/utils.test.ts
pnpm format                  # prettier --write .
pnpm generate-static-pages   # regenerate public/**/index.html from page components
pnpm generate-sitemap        # regenerate public/sitemap.xml
```

There is no CI; run `pnpm check` and `pnpm build` before pushing.

## Architecture

### Two rendering layers for every marketing route

1. **React SPA** (`client/src/`): React 19 + **wouter** routing (not react-router) + Tailwind 4 + shadcn/Radix UI. All routes are declared in `client/src/App.tsx` with lazy imports. Path alias `@` → `client/src`.
2. **Pre-rendered static HTML** (`public/<route>/index.html`): generated by `scripts/generate-static-pages.mjs`, which **regex-parses the `.tsx` page source files** (it does not compile them) to extract props, then emits standalone crawler-facing HTML with meta tags and JSON-LD schema. At build time a custom Vite plugin in `vite.config.ts` (`vitePluginCopyStaticFiles`) copies `public/` into `dist/public/` and injects the hashed built `<script>`/`<link>` tags into every static page, so browsers hydrate the full React app on top while non-JS crawlers see real unique HTML.

**Consequence of the regex extraction:** props in suburb page components must stay in shapes the generator can parse — `title="..."`, `` title={`...`} ``, `const suburb = "..."`, `neighbouringSuburbs={[{ name: "...", link: "..." }, ...]}`, and a `const faqs = [{ question, answer }]` array using plain string or template literals. `${suburb}` interpolation in those strings is substituted by the generator. If you restructure how props are written, verify `pnpm generate-static-pages` still extracts the content (inspect the emitted `public/<route>/index.html`).

### Suburb landing pages

Each suburb page (`client/src/pages/<Suburb>Painters.tsx`) is a thin wrapper around `client/src/components/SuburbPageTemplate.tsx`, passing title/description/localExpertise/propertyTypes/neighbouringSuburbs/faqs/schema.

**Adding a new suburb page requires touching all of these:**
1. Create `client/src/pages/<Suburb>Painters.tsx` wrapping `SuburbPageTemplate`
2. `client/src/App.tsx` — lazy import + **two** routes: `/painter-<slug>` and `/painters-<slug>` (Keysborough is the exception: `/keysborough-painters`)
3. `scripts/generate-static-pages.mjs` — add to the `allSuburbPages` array
4. `scripts/generate-sitemap.mjs` — add to `ROUTES`
5. `client/src/components/SuburbPageTemplate.tsx` — add to `KNOWN_LANDING_PATHS`
6. `client/src/suburbsData.ts` — add coordinates/postcode entry (used for the embedded map)
7. Run `pnpm generate-static-pages && pnpm generate-sitemap` and commit the generated `public/` output

### SEO plumbing

- `client/src/components/SEOHead.tsx` upserts title/meta/canonical/JSON-LD client-side; the static generator produces the equivalent for crawlers. Keep the two consistent when editing a page.
- Canonical URLs use **trailing slashes** (`https://jetblackpainting.com/painter-toorak/`).
- `llms.txt`, `local-seo.json`, `robots.txt`, `sitemap.xml` exist both at repo root and in `public/` — **the `public/` copies are what get deployed**; keep them in sync if you edit either.
- Business facts (phone `0432 077 782`, email `jimmy@jetblackpainting.com`, review count, $10M insurance, 5-year guarantee) are hardcoded in multiple places: `llms.txt`, constants at the top of `scripts/generate-static-pages.mjs`, and various components. When one changes, grep and update everywhere.

### Serving & deployment

- **Production**: Cloudflare Worker (`wrangler.jsonc` + `worker/index.js`). The worker 301-redirects `www.` → apex, then serves `dist/public` static assets with SPA fallback. Deployment is automated via Cloudflare Workers Builds Git integration — pushing to the repo triggers a build and deploy (the Cloudflare bot comments deploy status on PRs). A broken `pnpm build` therefore breaks deploys; verify it locally before pushing.
- `server/index.ts` is a small Express server (bundled by esbuild in `pnpm build`, run via `pnpm start`) from the earlier Railway hosting; it force-redirects to https and serves `dist/public`. It is not the primary production path anymore.
- `DEPLOYMENT_GUIDE.md`, `OPTIMIZATION_SUMMARY.md`, `PERFORMANCE_OPTIMIZATIONS.md`, and `SPEED_OPTIMIZATION.md` predate the Cloudflare move (they reference the old Manus platform) — treat them as historical, not current instructions.

### Build output

`pnpm build` produces `dist/public/` (Vite client build + copied static pages with injected asset tags) and `dist/index.js` (bundled Express server). Vite build is configured in `vite.config.ts` with terser (drops `console.*`), manual vendor chunks, and Vite `root` set to `client/`.

## Testing

Testing is minimal: vitest with a single test file (`client/src/lib/utils.test.ts`). There is no test setup/config file; vitest runs with defaults.
